Source connectors ​

A channel has exactly one source connector. Nine types ship with the engine.

ConnectorGets data by
Channel ReaderReceiving from other channels on the same engine
Database ReaderPolling a JDBC database
DICOM ListenerAccepting DICOM associations
File ReaderPolling a local directory, FTP, SFTP, S3, SMB, or WebDAV
HTTP ListenerServing HTTP requests
JavaScript ReaderRunning a script on a schedule
JMS ListenerConsuming from a JMS queue or topic
TCP ListenerAccepting TCP connections, MLLP included
Web Service ListenerServing SOAP requests

Settings outside the connector's own fields ​

Three blocks sit above the connector's own configuration, and the type decides which of them you get.

Listener settings, on the four listeners: TCP Listener, HTTP Listener, Web Service Listener, and DICOM Listener.

SettingDescription
Local AddressAll interfaces (the default) binds 0.0.0.0. Specific interface binds the address you enter
Local PortPort to bind. Defaults differ per connector and are given below. The Ports in Use button lists the listener ports the engine is already using

Polling settings, on the three that poll rather than listen: Database Reader, File Reader, and JavaScript Reader. They poll on an interval, at a set time, or on a cron schedule. See Polling Settings.

Source settings, the only block all nine have: the source queue, the response selector, batch processing where the type supports it, and max processing threads. See Architecture.

Channel Reader ​

Receives messages from Channel Writer destinations on other channels, and from router calls in scripts. It has no fields of its own, and the Administrator shows No configurable settings. in their place. The source settings block above still applies, and what arrives is decided entirely by the sending side.

Database Reader ​

Polls a database for a result set. Whether that set becomes one message or one message per row is decided by Aggregate Results below. Write the query in SQL or build it in JavaScript.

SettingDefaultDescription
DriverPlease Select OneJDBC driver. Required, JavaScript mode included. See drivers and URL templates
URLJDBC connection URL
Username / PasswordDatabase credentials
Use JavaScriptNoBuild the query in JavaScript instead of SQL. Switches the SQL field below to JavaScript
Keep Connection OpenYesReuse the connection between polls rather than reconnecting. Unavailable in JavaScript mode
Aggregate ResultsNoYes turns the whole result set into one message, sets Cache Results to Yes, and greys it out. No turns each row into its own message
Cache ResultsYesHold the whole result set in memory before processing. No streams from the cursor instead, and is what enables Fetch Size. Unavailable in JavaScript mode
Fetch Size1000JDBC ResultSet fetch size used when reading from the current cursor position. Applies only when Cache Results is No, and is greyed out otherwise, so at the default settings it does nothing
# of Retries on Error3Attempts after a failed poll before giving up
Retry Interval (ms)10000Wait between those attempts
EncodingDefaultCharacter set used to convert binary column values (byte arrays and blobs) to text. Text columns are not affected
SQL / JavaScriptThe select. The Generate buttons above it build a starting statement, or in JavaScript mode a connection block, from the settings above. In SQL mode each ${} is bound as a parameter rather than pasted in as text; see Where Velocity is used
Run Post-Process SQL / Run Post-Process ScriptNeverNever, After each message, or Once after all messages. Runs a second statement after the message has been processed. With Aggregate Results Yes the options read For each row and Once for all rows. In JavaScript mode, After each message and For each row give the script a resultMap variable holding the row. Once for all rows gives it a results variable holding a list of maps, one per row, when the select script returned a ResultSet; when the script returned a List, the post-process does not run. Once after all messages, with Aggregate Results No, runs after each poll with neither variable

The select runs again on every poll, so unless something changes the data it reads or the query itself, the same rows come back.

JavaScript mode

Choosing Use JavaScript disables three of the settings above: Keep Connection Open, Cache Results, and Fetch Size. The connector opens no database connection at all in this mode. The script opens its own, and has to return either a ResultSet or a List<Map<String, Object>>. A poll returning anything else fails. Aggregate Results applies only when the script returns a ResultSet; a returned List produces one message per map.

The four settings at the top of the connector still matter in this mode. Driver is required whether or not you use a script: the Administrator refuses to save the channel while it reads Please Select One, and there is no blank option. URL is validated only when Use JavaScript is No, and Username and Password are never validated. All four feed the generators. Generate: Connection, enabled only in this mode, pastes their current values, the password in plain text among them, into a connection block at the top of the script.

javascript
var dbConn;

try {
    dbConn = DatabaseConnectionFactory.createDatabaseConnection('<driver>','<url>','<username>','<password>');

    // You may access this result below with $('column_name')
    return result;
} finally {
    if (dbConn) {
        dbConn.close();
    }
}

The block is not runnable as generated. result is never assigned, so returning it fails the poll until you add the query yourself. Generate: Select is what adds it: it opens a live connection using those same four settings, which makes it the one place they are checked before a deploy, and inserts a dbConn.executeCachedQuery(...) line at the caret for the table you pick. The Post-Process JavaScript field has its own pair of buttons that do the same with executeUpdate.

Once generated, the driver, URL and credentials are string literals in the script. Editing the fields afterwards does not change them, and the connector's own copies are never read at runtime.

Clicking the Use JavaScript radio rewrites both script fields: Yes replaces their contents with the generated block, No empties them. Reopening a saved channel does not, so this happens only while editing.

DICOM Listener ​

Accepts DICOM associations and stores received objects as messages. Default port 104.

SettingDefaultDescription
Application EntityAE title this listener answers to. Blank accepts any
Store Received Objects in DirectoryHas no effect. A received object becomes a message, and nothing is written to this directory
Max Async operations0Maximum outstanding asynchronous operations. 0 leaves the DICOM library's default, which the field's tooltip gives as unlimited
Pack PDVNoPack the command and data PDVs into a single P-DATA-TF PDU
Only Accept Default Transfer SyntaxNoRefuse anything but implicit VR little endian
Only Uncompressed Pixel DataNoRefuse compressed transfer syntaxes
Accept Explict VR Big EndianNoYes does not enable big endian: it limits the listener to the implicit VR little endian transfer syntax, as described below. The label carries the engine's own spelling

The three transfer syntax options above reset each other: Yes on Only Accept Default Transfer Syntax greys out the other two and sets them to No, and Yes on Only Uncompressed Pixel Data or Accept Explict VR Big Endian greys out Only Accept Default Transfer Syntax. In this build any Yes limits the listener to the implicit VR little endian transfer syntax. With all three at No, the listener keeps its default set of transfer syntaxes.

File Reader ​

Polls a location and turns files into messages.

Method is the first field on the panel. It decides how the location is addressed, whether credentials apply, and which connection settings are available.

MethodLocation fieldsCredentialsConnection settings enabled
fileDirectorynonenone
ftpftp:// host, pathAnonymous, or username and passwordTimeout, Passive Mode, Validate Connection, Advanced Options
sftpsftp:// host, pathno Anonymous option; the fields stay editableTimeout, Advanced Options
smbsmb:// host, pathno Anonymous option; the fields stay editableTimeout, Advanced Options
webdavhttp:// or https:// host, pathAnonymous, or username and passwordSecure Mode
Amazon S3S3 Bucket, pathAnonymous, or AWS Access Key ID and Secret Access KeyTimeout, Advanced Options

Timeout must not be left blank for FTP, SFTP, or SMB. file is the only method with a single Directory field; the others split the location into a host and a path, with the protocol prefix as the host's label. Secure Mode is what switches WebDAV between http:// and https://. An installed extension that adds TLS to the File Reader changes the FTP prefix to ftps://. Under S3 the credential fields are relabelled AWS Access Key ID and AWS Secret Access Key, and the move-to fields become Move-to S3 Bucket / Directory.

Broken in 4.7.0

A File Reader set to webdav fails to start, and the server log shows NoClassDefFoundError: org/jdom/input/DOMBuilder. Fix proposed in engine PR #546, not yet in a release.

On Windows, Directory under file can be a UNC path such as \\server\share\inbound. The Administrator stores it with forward slashes, //server/share/inbound, which Windows still reads as the same share. The account the OIE service runs as needs access to the share. On Linux, mount the share, in /etc/fstab or with an automounter, and point the file method at the mount point.

The remaining settings, in the order they appear:

A blank directory leaves the file where it is, a blank file name keeps the original one, and an existing file at the destination is deleted first

A move happens on the server the file was read from

A move runs over the same connection the file was read from. Under sftp the move-to directory is a directory on the SFTP server, under ftp on the FTP server, and under smb a path on the same SMB server. It cannot be a directory on the OIE server, and nothing is copied back to the OIE server on the way. Only the file method moves files on the OIE server's own disk, because that is where it reads from. The same goes for Error Move-to Directory, and for the Delete actions, which delete on the remote side.

Relative paths resolve differently per method. FTP and SFTP change to the read directory first, so a path with no leading / is taken relative to the directory being read, and a leading / is absolute on the remote host. SMB resolves it against the server, so the first part of a relative path is the share name, for example share/archive. Under file a relative path resolves against the engine's working directory, not the directory being read, so use an absolute path. WebDAV paths always start from the server root. S3 reads the field as a bucket and a prefix, which is why it is labelled Move-to S3 Bucket / Directory and why a move can cross buckets. Backslashes typed into either move-to directory field are converted to forward slashes when the channel is saved. A move-to directory that does not exist is created.

The wrench button beside Method opens a per-protocol dialog, and the Advanced Options row below it shows a read-only summary of what is set. See file protocol advanced settings.

HTTP Listener ​

Serves HTTP requests. Default port 80, and the HTTP URL shown on the panel is built from the address of the server the Administrator is connected to, the Local Port, and the Base Context Path.

SettingDefaultDescription
Base Context PathPath this connector answers on. Blank means the root, not nothing. See below
Receive Timeout (ms)30000Maximum idle time for a connection
Request Header Size (bytes)8192Maximum combined size of all request headers. Larger requests are rejected with 431 Request Header Fields Too Large before the channel sees them. Template substitutions are allowed, and the value must resolve to a positive whole number, or the connector fails to start
Message ContentPlain BodyPlain Body passes the body through. XML Body wraps the body in XML, and with Include Metadata set to Yes it also adds the remote address, request URL, method, path, context path, parameters, and headers
Parse MultipartYesSplit a multipart request into parts. XML Body only
Include MetadataNoInclude method, context path, headers, and query parameters. XML Body only
Binary MIME Typesapplication/.*(?<!json|xml)$|image/.*|video/.*|audio/.*Content types treated as binary and base64 encoded. Regular Expression switches it between a regex and a plain list
Response Content Typetext/plainValue of the response's Content-Type header
Response Data TypeTextText or Binary. Binary base64 decodes the response before sending
Charset EncodingUTF-8Character set. Disabled when Response Data Type is Binary
Response Status CodeHTTP status to return. Blank returns 200, or 500 when the selected response has status ERROR
Response HeadersHeaders to return. Use Map takes them from a map variable instead of the table
Static ResourcesPaths served directly by the connector, each with its own content type and value, without producing a message

The engine normalizes Base Context Path: a leading slash is added if you left it off, and a trailing slash is stripped, so orders, /orders, and /orders/ all give the same context, and blank and / are the same thing. A listener answers its context path with the trailing slash, such as /orders/, and everything below it. A request to /orders without the slash gets a 302 redirect to /orders/, and a POST to /orders is not delivered to the channel, so send to /orders/. At the root it answers every request that reaches its port.

Each HTTP Listener builds its own server bound to its own host and port, so two channels cannot share a port and divide it by context path. Static resource paths are appended to the base.

Authentication is a separate plugin; see HTTP authentication.

JavaScript Reader ​

Runs a script on the polling schedule. The script's return value becomes the message, a returned Java List produces one message per element, and returning nothing produces no message.

SettingDescription
JavaScriptThe script to run

This connector's scope is narrower than most: it has no channelMap, connectorMap, sourceMap, responseMap, or connectorMessage, because the script runs before any message exists. The JavaScript Writer does have them. See Script Scope and User API.

The listener answers every SOAP request with an HTTP 500, while its WSDL still loads. Engine issue #509 reports this on Java 19 and later; a fix is proposed in engine PR #508, not yet in a release. Until then, run the engine on Java 17, or add the -classpath/a line from engine issue #509 to conf/custom.vmoptions.

File protocol advanced settings ​

Reached through the wrench button beside Method on the File Reader and the File Writer. The dialog's contents depend on the selected method. Passive mode, secure mode, and the timeout are not in these dialogs; they are on the main connector panel. The S3 dialog has no bucket field, because the bucket is the S3 Bucket field on the main panel, and there is no domain field for SMB.

  • FTP: Initial Commands
  • SFTP: Authentication, Public/Private Key File, Passphrase, Host Key Checking, Known Hosts File, and a free-form Configuration Options map
  • S3: Use Default Credential Provider Chain, Use Temporary Credentials, Duration (seconds), Region, Custom HTTP Headers
  • SMB: SMB Minimum Version, SMB Maximum Version

For S3 the generic Username and Password fields are relabelled AWS Access Key ID and AWS Secret Access Key on the main panel.

HTTP authentication ​

HTTP authentication is a plugin that ships with the engine. It adds authentication to the HTTP Listener and the Web Service Listener, with these methods:

  • Basic Authentication: username and password
  • Digest Authentication: digest challenge and response
  • JavaScript: authentication logic you write
  • Custom Java Class: authentication delegated to a class you supply
  • OAuth 2.0 Token Verification: validates an incoming OAuth 2.0 token
