Destination connectors ​

A channel has at least one destination and may have many. Each has its own filter, transformer, and connector, and it does not have to send anything: its filter can stop the message, and a JavaScript Writer may only run a script. Eleven types ship with the engine.

ConnectorSends data by
Channel WriterHanding the message to another channel on the same engine
Database WriterRunning a statement against a JDBC database
DICOM SenderOpening a DICOM association to a remote AE
Document WriterRendering a PDF or RTF
File WriterWriting to a local directory, FTP, SFTP, S3, SMB, or WebDAV
HTTP SenderMaking an HTTP request
JavaScript WriterRunning a script
JMS SenderPublishing to a JMS queue or topic
SMTP SenderSending email
TCP SenderOpening a TCP connection, MLLP included
Web Service SenderCalling a SOAP operation

Settings outside the connector's own fields ​

One block sits above the connector's own configuration, and every destination type has it. It controls the queue and what happens when a send fails. Queue Messages, Validate Response and Reattach Attachments are on the panel itself; the rest open from the wrench button beside Advanced Queue Settings. The queue-only settings are greyed out while Queue Messages is Never, and the retry settings stay available for Never and On Failure.

SettingDefaultDescription
Queue MessagesNeverNever, On Failure, or Always. Decides whether a failed send, or every send, goes to this destination's queue. Not every failure queues: a refused connection does, but a JavaScript Writer script that throws gives ERROR and is not queued; return QUEUED from the script to queue the message. On Failure sends directly only while the queue is empty; otherwise a new message joins the queue. See Queueing
Retry Count Before Queue/Error0Retries after the first failed attempt before the message queues or errors, so 0 means one attempt. Enabled only when Queue Messages is Never or On Failure
Retry Interval (ms)10000Wait between those attempts. Enabled when the queue is on or Retry Count Before Queue/Error is above 0
Rotate QueueNoMove a failing message to the back of the queue instead of blocking behind it. Queue on only
Queue Threads1Threads draining the queue. More than one drains it in parallel, so order is no longer guaranteed except within a Thread Assignment Variable group. Queue on only
Thread Assignment VariableGroups messages onto the same queue thread, so ordering is kept within a group when Rotate Queue is No. Enabled only when Queue Threads is above 1
Queue Buffer SizeDefault Queue Buffer Size from SettingsMessages held in memory before falling back to the database. The Administrator fills in the Settings value for a new destination and refuses to save a value of 0 or less. Queue on only
Include Filter/TransformerNoRe-run the destination's filter and transformer on each queue retry. Enabled only when the queue is on and Regenerate Template is Yes
Regenerate TemplateNoReplace the variables in the template and the other connector settings again on each retry, picking up map changes. Queue on only
Validate ResponseNoRun the response validator of the response transformer's inbound data type on the reply. This works only when that data type has a Response Validation section; a failed validation marks the message queued or errored. For HL7 v2, an error or rejected ACK, or a control ID that does not match, gives ERROR; a blank reply, or one that is not a valid ACK, gives QUEUED, which becomes ERROR when the queue is off. Available on the Channel Writer, Database Writer, HTTP Sender, JavaScript Writer, TCP Sender, and Web Service Sender, and greyed out on the DICOM Sender, Document Writer, File Writer, JMS Sender, and SMTP Sender. The TCP Sender is the only type that ships with this on
Reattach AttachmentsYesRe-insert attachment content before sending. No effect on the JMS Sender or the JavaScript Writer

The queue is off by default on every destination.

Field values are run through Velocity replacement before the send, so a directory, a filename, a URL, a subject line, or a header can carry data from the message. The JavaScript Writer is the exception: it has no templated fields.

Channel Writer ​

Hands the message to another channel on the same engine. A Channel Reader is the usual receiver, but the target channel's source does not have to be one: a channel with an HTTP Listener source receives the message and runs its destinations.

SettingDefaultDescription
Channel IdnoneThe receiving channel
Template${message.encodedData}What the receiving channel gets as its raw message
Message MetadataMap variables to pass along. They arrive in the receiving channel's source map, not its channel map

Database Writer ​

Runs an insert, update, or delete against a database. Write it in SQL or build it in JavaScript.

SettingDefaultDescription
DriverPlease Select OneJDBC driver. Required, JavaScript mode included. See drivers and URL templates
URLJDBC connection URL
Username / PasswordDatabase credentials
Use JavaScriptNoBuild the statement in JavaScript instead of SQL
SQL / JavaScriptThe statement. The Generate buttons above it build a starting statement, or in JavaScript mode a connection block, from the settings above. In SQL mode each ${} is bound as a parameter rather than pasted in as text; see Where Velocity is used

JavaScript mode

As on the Database Reader, the connector opens no database connection in this mode and the script opens its own. Driver is required either way. While it reads Please Select One the Administrator saves the channel disabled and shows an error dialog listing the problem. URL is validated only when Use JavaScript is No, and the credentials are never validated. Generate: Connection, enabled only in this mode, pastes all four values, the password in plain text among them, into a connection block at the top of the script, and Generate: Insert inserts a dbConn.executeUpdate(...) line at the caret for the table you pick. Those values are string literals in the script from then on. Editing the fields does not change them, and the connector's own copies are never read at runtime.

The generated block opens a connection and closes it in a finally, with nothing in between until you add the statements yourself. What the script returns decides the response: nothing at all is a SENT with Database write success, a Response is used as-is, a Status sets only the status, and anything else becomes the response data.

Clicking the Use JavaScript radio rewrites the script field: Yes replaces its contents with the generated block, No empties it. Reopening a saved channel does not.

File Writer ​

Writes the message to a file. Method is the first choice: it decides how the location is addressed, whether credentials apply, which connection fields are available, and which File Exists options you get.

Method ​

fileDirectory, a single fieldnonenothing
ftpftp:// host, then a pathAnonymous, or a username and passwordPassive Mode, Validate Connection, Timeout, Advanced Options
sftpsftp:// host, then a pathA username always, and a password unless the Advanced Options use a different authenticationTimeout, Advanced Options
Amazon S3S3 Bucket, then a pathAnonymous, or an AWS Access Key ID and Secret Access Key. Neither is required when the Advanced Options use the default credential provider chainTimeout, Advanced Options

webdavhttp:// or https:// host, then a pathAnonymous, or a username and passwordSecure Mode

Two methods restrict what else you can choose. Append is not available under S3 or WebDAV, so File Exists offers only Overwrite and Error, and selecting either method switches an existing Append setting to Overwrite. S3 additionally forces Create Temp File to No. Under S3 the credential fields are relabelled AWS Access Key ID and AWS Secret Access Key.

Broken in 4.7.0

A File Writer set to webdav writes nothing: the message is left at RECEIVED, and the server log shows NoClassDefFoundError: org/jdom/input/DOMBuilder. Fix proposed in engine PR #546, not yet in a release.

On Windows, Directory under file can be a UNC path such as \\server\share\outbound. The Administrator stores it with forward slashes, //server/share/outbound, which Windows still reads as the same share. The account the OIE service runs as needs access to the share. On Linux, mount the share, in /etc/fstab or with an automounter, and point the file method at the mount point.

JavaScript Writer ​

Runs a script, which can send data anywhere itself or nowhere at all. What the script returns decides the response: nothing at all is a SENT with JavaScript evaluation successful., a Response is used as-is, a Status sets only the status, and anything else becomes the response data. A script that throws gives ERROR.

SettingDescription
JavaScriptThe script to run

Unlike the JavaScript Reader, this connector has the full message scope: channelMap, connectorMap, sourceMap, responseMap, and connectorMessage are all available. See Script Scope and User API.

JMS Sender ​

Publishes to a JMS queue or topic. The connection fields are the same as the JMS Listener, except that there is no Durable checkbox: Use JNDI, Provider URL, Initial Context Factory, Connection Factory Name, Connection Factory Class, Connection Properties, Username, Password, Client ID, Destination Type, and Destination Name. Use JNDI Yes greys out Destination Type and Connection Factory Class. No greys out Provider URL, Initial Context Factory, and Connection Factory Name. As for the JMS Listener, select the library resource with the provider's client jars on this destination's own entry in Set Dependencies > Library Resources; without it the send is ERROR with a ClassNotFoundException for the factory class.

SettingDefaultDescription
Template${message.encodedData}Message body published
